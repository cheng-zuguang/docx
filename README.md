# docx

English | [中文](README.zh-CN.md)

`docx` is a Go CLI for creating and maintaining AI-readable project context.

It creates a `.doc/` directory and a small `.docx.json` config file in any
repository. AI agents start from `.doc/index.json`, then progressively read only
the project, module, decision, mistake, change, or proposal files that matter for
the current task.

## Why Use It

Use `docx` when a repository has enough history or structure that every new AI
session spends time rediscovering the same context.

Common scenarios:

- **New AI session onboarding**: initialize `.doc/` once so agents can read a
  compact project router instead of scanning the whole repository.
- **Team project memory**: keep project facts, module boundaries, decisions,
  mistakes, and recent changes in versioned files.
- **Pre-commit context updates**: record staged changes before committing so the
  context stays close to the code.
- **Large or modular repositories**: use `moduleMap` to route changed files to
  focused module context.
- **AI-assisted semantic updates**: let local AI tools propose updates while the
  CLI keeps confirmed semantic memory behind explicit approval.
- **Multi-language repositories**: start with generic scanning and add analyzers
  as deeper language support becomes available.

## Core Idea

`docx` separates generated facts from confirmed semantic memory.

- Generated facts can be refreshed by the CLI.
- Semantic memory such as decisions, mistakes, module summaries, and risk rules
  should be changed only through confirmation or accepted proposals.
- Managed blocks are used for `AGENTS.md`, `CLAUDE.md`, `.gitignore`, and hooks
  so existing user-authored content is preserved.

## Install

macOS and Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/cheng-zuguang/docx/main/install.sh | sh
```

Windows PowerShell:

```powershell
iwr https://raw.githubusercontent.com/cheng-zuguang/docx/main/install.ps1 -UseB | iex
```

npm:

```bash
npm install -g @chengzg/docx
docx --help
```

npx:

```bash
npx @chengzg/docx --help
npx @chengzg/docx init
```

Development:

```bash
go test ./...
go run ./cmd/docx --help
go run ./cmd/docx init
```

## Generated Structure

Default layout with file meanings:

```text
.docx.json                    # CLI config: context dir, schema version, entry files, AI command settings
.doc/
|-- index.json                # Context router: project summary, readOrder, moduleMap
|-- project.json              # Project-level generated facts and high-level summary
|-- capabilities.json         # Available analyzers and missing recommended analyzers
|-- README.md                 # Local note for humans: this directory is generated by docx
|-- rules/
|   `-- agent.md              # Reading protocol for AI agents
|-- modules/
|   `-- <module>.json         # Module context: paths, status, facts, hints, risks, recent changes
|-- changes/
|   |-- index.json            # Rebuildable index of change records
|   |-- <change-id>.json      # Machine-readable change record
|   `-- <change-id>.md        # Human-readable change record
|-- proposals/
|   |-- index.json            # Rebuildable index of semantic update proposals
|   |-- <proposal-id>.json    # Machine-readable pending/accepted/rejected proposal
|   `-- <proposal-id>.md      # Human-readable proposal audit note
|-- decisions/
|   `-- index.json            # Rebuildable index of confirmed design decisions
|-- mistakes/
|   `-- index.json            # Rebuildable index of confirmed anti-pattern notes
|-- .cache/                   # Local cache, ignored by git
|-- local/                    # Local machine/user state, ignored by git
`-- tmp/                      # Temporary files, ignored by git
```

`.doc/.cache/`, `.doc/local/`, and `.doc/tmp/` are local state and are ignored
through a managed `.gitignore` block.

## Commands

### `docx init`

Initialize project context.

```bash
docx init
docx init --dir .context
docx init --entry AGENTS.md --entry CLAUDE.md
docx init --non-interactive
docx init --accept-candidates
docx init --interactive
```

Behavior:

- Creates `.docx.json` and the `.doc/` structure.
- Scans manifests, languages, frameworks, entrypoints, tests, config files, and
  module candidates.
- Inserts a managed block into AI entry files.
- When no `--entry` is provided, updates existing `AGENTS.md` / `CLAUDE.md`; if
  neither exists, creates only `AGENTS.md`.
- Does not install git hooks by default.

Interactive module confirmation:

```text
accept chat
ignore temp
rename billing payments
merge platform api,web
done
```

Use this when scanner-detected module boundaries need human confirmation before
future updates rely on them.

### `docx scan`

Inspect what `docx` can detect without updating semantic memory.

```bash
docx scan
docx scan --json
docx scan --analyzer generic
docx scan --analyzer typescript
docx scan --analyzer ./tools/my-analyzer
```

Use it to debug project discovery, verify analyzer output, or inspect module
candidates before running `init --interactive`.

### `docx update`

Record code changes and refresh generated context facts.

```bash
docx update --staged
docx update --changed
docx update --since HEAD~1
docx update --module chat
```

Typical workflows:

```bash
# Before committing
docx update --staged

# After editing a module locally
docx update --changed

# After merging a branch
docx update --since main
```

The command writes both machine-readable and human-readable change records under
`.doc/changes/`, then updates affected module `recentChanges`.

### `docx update --ai`

Generate semantic proposals without directly changing confirmed memory.

```bash
docx update --staged --ai
docx update --changed --ai --ai-command "codex exec --json"
docx update --changed --ai --ai-command "ollama run qwen2.5-coder"
docx update --since HEAD~1 --ai --ai-command "claude -p"
```

Without a local AI command, `docx` creates provider-agnostic placeholder
proposals. With `--ai-command`, it sends stable JSON through stdin and expects a
proposal object or proposal array on stdout.

You can also configure the local command in `.docx.json`:

```json
{
  "ai": {
    "provider": "local-command",
    "command": "codex exec --json",
    "timeoutSeconds": 120,
    "contextSources": ["docx", "codegraph"],
    "output": "proposal-json"
  }
}
```

Command-line `--ai-command` overrides `.docx.json.ai.command`.

### `docx proposals`

Review and apply semantic proposals.

```bash
docx proposals list
docx proposals show <id>
docx proposals accept <id>
docx proposals accept <id> --target .doc/mistakes/testing.md
docx proposals reject <id>
```

Use this to keep long-term memory deliberate. Accepted proposals can update
decisions, mistakes, module summaries, or module risk rules; rejected proposals
keep audit history.

### `docx index`

Rebuild or check indexes.

```bash
docx index
docx index --check
docx index --section changes
docx index --section proposals
docx index --section decisions
docx index --section mistakes
```

Use it after merges, manual edits, or proposal workflow changes.

### `docx doctor`

Check installation health.

```bash
docx doctor
docx doctor --json
docx doctor --strict
```

It checks config, required files, schema versions, indexes, analyzer
capabilities, and optional hook state. `--strict` is intended for CI.

### `docx migrate`

Run explicit schema migration.

```bash
docx migrate
```

`docx update` stops on major schema mismatch and asks you to run migration
instead of silently changing context formats.

### `docx install-hook`

Install optional git hooks with managed blocks.

```bash
docx install-hook pre-commit
docx install-hook post-merge
docx install-hook post-checkout
```

Existing hook content is preserved. Re-running the command refreshes the managed
block without duplicating it.

For hook managers:

```bash
# Husky pre-commit body
docx update --staged
```

```yaml
# lefthook.yml
pre-commit:
  commands:
    docx:
      run: docx update --staged
```

## End-To-End Examples

### Bootstrap a repository for AI agents

```bash
docx init --interactive
git add .doc .docx.json AGENTS.md .gitignore
```

Then future agents can read `AGENTS.md`, follow the managed block to
`.doc/index.json`, and progressively load context.

### Keep context fresh before each commit

```bash
git add internal/cli/update.go internal/cli/update_test.go
docx update --staged
git add .doc/changes .doc/modules
```

This records what changed and links the change to affected modules.

### Let a local AI tool suggest memory updates

```bash
docx update --changed --ai --ai-command "codex exec --json"
docx proposals list
docx proposals show <id>
docx proposals accept <id>
```

The local AI suggests semantic updates, while `docx` controls validation,
storage, and explicit acceptance.

### Recover after a merge

```bash
docx index
docx doctor
```

Use this when index files may be stale or when a teammate changed `.doc/`
manually.

## Analyzer Support

Current analyzer layers:

- `generic`: built into the Go CLI and works for any repository.
- `typescript` / `javascript`: optional Node analyzer for package manifests,
  imports, exports, framework signals, routes where practical, and tests.
- External analyzers: called through the analyzer plugin protocol.

Roadmap details live in [docs/analyzers/protocol.zh-CN.md](docs/analyzers/protocol.zh-CN.md).
